A harness is the coding agent that runs your sessions: OpenCode, Codex, Claude Code, or Antigravity. OpenDucktor uses the [models](/models/) of your sign-in to the harness.

## Install a harness [#install]

Install the harness and sign in to it with its own tool. Then turn it on in OpenDucktor.

| Harness | Minimum version | Install and sign in | Update |
|---|---|---|---|
| OpenCode | 2 or later | [OpenCode documentation](https://opencode.ai/docs) | `opencode upgrade` |
| Codex | With `codex app-server` | [Codex documentation](https://developers.openai.com/codex) | `codex update` |
| Claude Code | 2.1.306 or later | [Claude Code documentation](https://code.claude.com/docs/en/overview) | `claude update` |
| Antigravity CLI | 1.5.14 or later | [Antigravity documentation](https://antigravity.google/docs/cli). To sign in, run `agy` in a terminal. | `agy update` |

OpenDucktor uses the sign-in and the settings of each harness. It does not ask for your credentials.

<Callout type="info" title="Claude subscriptions">To use Claude Code with a Claude subscription, read [Use the Claude Agent SDK with your Claude plan](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan).</Callout>

## Turn on a harness [#set-up-a-harness]

The setup wizard turns on the harnesses that you choose. Use these steps to turn one on later.

<Steps>
<Step>Open [**Settings**](/settings-reference/#open-settings), then **Agent runtimes**, then the harness. Settings shows Claude Code as **Claude**.</Step>
<Step>Turn on **Enabled**. If the harness does not show **Available**, select <Action>Browse</Action> and choose its executable.</Step>
<Step>Select <Action>Save settings</Action>.</Step>
</Steps>

<Screenshot id="settings-harnesses" alt="The Agent runtimes section of Settings. OpenCode, Antigravity, Claude, and Codex show Enabled. The OpenCode card shows Available, the Enabled switch, the executable path with Browse, and the version with Check again." />

If the harness shows **Needs attention**, see [Troubleshooting](/troubleshooting/#harness-needs-attention).

## What each harness supports [#capabilities]

All four harnesses run every agent role. Each one supports questions, permission requests, attachments, skills with `$`, and slash commands. They differ in these features:

| Feature | OpenCode | Codex | Claude Code | Antigravity |
|---|---|---|---|---|
| Session forks | Yes | Yes | Yes | No |
| [Steer a message](/coding-sessions/#queue) | 2.0.24 or later | 0.106.0 or later | Yes | Yes |
| [Goal mode](/coding-sessions/#goal-mode) | 2.2.1 or later | 0.166.0 or later | Yes | Yes |
| <Action>Pause goal</Action> and <Action>Resume goal</Action> | Yes | Yes | No | No |
| <Action>Stop session</Action> during a goal | Pauses the goal | Pauses the goal | Keeps the goal | Keeps the goal |
| Image generation | No | Yes | No | No |
| [Resume a stopped turn](/coding-sessions/#resume-turn) | Yes | Yes | Yes | No. Send a new message. |
| [Auto-resume after a usage limit](/coding-sessions/#usage-limit) | No | Yes, with a ChatGPT sign-in | Yes | No |
| [Stop one background task](/coding-sessions/#stop-background-task) | Yes | 0.140.0 or later | Yes | No. Stop the session. |
| [**Speed** choice](/models/#session-model) | No | Some models | Some models | No |
| [**Profile** choice](/models/#session-model) | Yes | No | No | No |
| Todo list in the session | No | Yes | Yes | No |
| Subagents in the background | Yes | No | Yes | No. A subagent shows as a tool call. |
| Mention a subagent with `@` | Yes | No | No | No |
| [Switch to another harness](/models/#runtime-handoff) | Yes | 0.136.0 or later | Yes | Yes |
| Session titles from the [Naming model](/workspace-sessions/#naming-model) | Yes | Yes | Yes | No. Sessions keep the Antigravity title. |
| [Permission replies](/coding-sessions/#answer-a-permission-request) | <Action>Approve once</Action>, <Action>Allow for project</Action>, <Action>Reject</Action> | <Action>Approve once</Action>, <Action>Approve for session</Action>, <Action>Always allow</Action>, <Action>Reject</Action> | <Action>Approve once</Action>, <Action>Reject</Action> | <Action>Approve once</Action>, <Action>Reject</Action> |

## Control what agents can do [#permissions]

Each harness has its own permission settings in **Agent runtimes**.

<Steps>
<Step>In **Agent runtimes**, select the harness.</Step>
<Step>Set the default value of each field. For Claude Code, open the group of the field first. To give one role another value, turn on **Role overrides** for the field.</Step>
<Step>If the section asks you to confirm reduced protections, turn on the confirmation switch.</Step>
<Step>Select <Action>Save settings</Action>.</Step>
</Steps>

<Screenshot id="settings-codex-policy" alt="The Sandbox mode card of the Codex settings. The default is Workspace-write. Role overrides is on, with Spec, Planner, and QA set to Read-only and Builder set to Inherited." />

| Harness | Setting | What it does |
|---|---|---|
| OpenCode | [OpenCode permissions](/settings-reference/#harnesses-opencode-permissions) | Allows, asks about, or denies each command, file access, or web fetch. |
| Codex | [Sandbox mode](/settings-reference/#harnesses-codex-sandbox-mode) | Sets what Codex can change. |
| Codex | [Approval prompts](/settings-reference/#harnesses-codex-approval-prompts) | Sets when Codex asks you. |
| Codex | [Prompt reviewer](/settings-reference/#harnesses-codex-prompt-reviewer) | Sets who reviews approval prompts: you or the Codex automatic review. |
| Codex | [Command network access](/settings-reference/#harnesses-codex-command-network-access) | Lets commands in sandboxed turns use the network. |
| Claude Code | [Approval mode](/settings-reference/#harnesses-claude-approval-mode) | Sets when Claude Code asks you. |
| Claude Code | [Bash sandbox](/settings-reference/#harnesses-claude-bash-sandbox) | Runs shell commands in a sandbox. |
| Antigravity | [Session mode](/settings-reference/#harnesses-antigravity-session-mode) | Sets what Antigravity approves without asking you. |

The settings apply in this order:

<Diagram name="permissionOrder" />

In Codex, a command in the **Workspace-write** sandbox can change files without a request. To stop the Spec, Planner, and QA roles from changing files with Codex, set their **Sandbox mode** to **Read-only** in **Role overrides**.

In Antigravity, OpenDucktor refuses the file edits of Spec, Planner, and QA in every **Session mode**. Their shell commands follow the mode, so a command can still change a file.

<Callout type="warn" title="Reduced protections">
These settings let agents act without your approval or outside the sandbox:

- Codex **Sandbox mode**: **Danger full access**
- Codex **Approval prompts**: **Never**
- Claude Code **Approval mode**: **Bypass permissions**
- Claude Code **Bash sandbox**: off

Use them only in a repository that you trust.
</Callout>
