Each agent role has a default model, and you can change the model, effort, or speed of one session. Each [harness](/harnesses/) lists the models that your harness account can use.

## Set the default models [#role-defaults]

<Steps>
<Step>Open [**Settings**](/settings-reference/#open-settings), then **Repositories**, your repository, and **Agents**.</Step>
<Step>Under **Default model**, open the model picker and select a model. In the options at the bottom of the picker, set the **Effort**, the **Profile** for OpenCode, or the **Speed**.</Step>
<Step>Optional: to give a role another model, select it under **Agent defaults by role**.</Step>
<Step>Select <Action>Save settings</Action>.</Step>
</Steps>

A role can use a model of another harness. For example, Spec can use Claude Code while the Builder uses Codex.

## Which model a session uses [#model-choice]

A new task session uses the first model that is set.

<Diagram name="modelChoice" />

- For a fresh session, the start dialog shows the role default, or the **Default model** if the role has none. You can change the model before you start.
- Under [**Session mode**](/coding-sessions/#start-a-session), **Fork existing** shows the model of the source session. You can change it. <Action>Generate Pull Request</Action> offers **Fork existing**, and forks a Builder session.
- **Reuse existing** keeps the model of the session that you reuse. You cannot change it.
- A new [workspace session](/workspace-sessions/) uses the **Default model**.
- When [Autopilot](/autopilot/) starts a fresh session, it uses these defaults. Without a role default or a **Default model**, Autopilot cannot start the role.
- If a saved model is no longer available, the start dialog shows no model, and Autopilot cannot start the role. Choose another model.
- Running sessions keep their model.

## Change the model of one session [#session-model]

<Steps>
<Step>In the [start dialog](/coding-sessions/#start-a-session), open **Runtime and model**. In the composer of a running session, select the model under the message box.</Step>
<Step>Select a harness in the rail on the left, then a model in the list.</Step>
<Step>If the model has options, set them at the bottom of the picker: **Effort**, **Profile**, or **Speed**.</Step>
</Steps>

The start dialog, the composer, and Settings use the same picker. When you have favorites, the picker opens on them. In the composer, a model of another harness moves the session to that harness. See [Continue a session in another harness](#runtime-handoff).

- **Effort** sets how much the model thinks before it answers. Only some models have it.
- **Profile** chooses an agent profile of the harness. To change it, start a new session.
- **Speed** shows only for the models that have it. **Standard** is the normal speed. A faster speed can cost more.

For the options of each harness, see [What each harness supports](/harnesses/#capabilities).

A change in the composer applies to the next turn.

## Continue a session in another harness [#runtime-handoff]

You can move a session to a model of another harness. The new harness continues in the same checkout, with the same role.

<Steps>
<Step>In the composer of a session, open the model picker. On mobile, open **Message options** first.</Step>
<Step>Select a model of another harness. The composer shows the two harnesses and the earlier content that the new harness gets.</Step>
<Step>Wait until the agent and its subagents stop. Answer the pending requests, clear the queue, then send your message.</Step>
</Steps>

The transcript marks the switch, and tells you if the earlier content did not fit. To cancel before you send, select <Action>Cancel</Action>, or a model of the current harness. If the switch does not complete, see [Troubleshooting](/troubleshooting/#handoff-not-delivered).
