OpenDucktor tells each agent of a task what to do with a set of prompts. You can add your instructions after any prompt, or replace the prompt, for all repositories or for one repository.

## What OpenDucktor sends [#what-it-sends]

### The system prompt [#system-prompt]

Each Spec, Planner, Builder, or QA session gets a system prompt: the rules that the agent follows for the whole session.

<Diagram name="systemPrompt" />

Each section is the final text of its prompt, with your changes. See [Which version applies](#precedence). OpenDucktor builds the system prompt again before each new message. A change applies from the next message.

To read the full system prompt of a session, open the session and select <Action>Show system prompt</Action> at the top of the conversation.

<PromptAnatomy />

Workspace sessions do not get these prompts. To give a workspace session its own instructions, use a [custom agent role](/workspace-sessions/#custom-roles).

### Kickoff prompts and messages [#kickoff-prompts]

<Diagram name="kickoffPrompts" />

[Autopilot](/autopilot/) runs the same actions. A task or a bug can skip the Spec and Planner steps. Then <Action>Start Builder</Action> shows in <Status of="open" />. A change to a kickoff prompt applies the next time that its action runs.

Two prompts do not start a step:

- **Builder Git Conflict Message** goes to the Builder session when a Git operation stops on conflicts.
- **Read-Only Permission Rejection** is the reply that a Spec, Planner, or QA agent gets when it asks for a tool that writes, such as a file edit.

You can change a prompt in two ways:

- **Append instructions** adds your text after the prompt. The built-in text keeps its updates when you update OpenDucktor. Use this when you can.
- **Replace the whole prompt** gives an override: your text replaces the built-in prompt. An override does not get the updates of the built-in prompt. See [Outdated overrides](#outdated).

A prompt can have an append and an override at the same time. Then your append goes after your override.

To give agents a code rule, such as your test command, write it in `AGENTS.md` or `CLAUDE.md` of your repository. The built-in prompts tell agents to follow these files. Change a prompt only to change how an agent works in OpenDucktor.

## Which version applies [#precedence]

<Diagram name="promptSources" />

**System prompts** change a prompt in all repositories. **Repository prompts** change it in one repository, on top of the System prompts:

- A repository override replaces the global override and the built-in prompt.
- A repository append goes after the global append. Both appends apply.

Each prompt is separate. If a repository overrides **Builder Kickoff**, its other prompts still use your global changes.

Open **Settings**, then **System prompts** for all repositories. For one repository, open **Repositories**, select the repository, then **Repository prompts**. Both screens work in the same way.

A badge on a prompt shows its state on the screen that you see:

| Badge | Meaning |
|---|---|
| **Appended** | The prompt has append instructions with text, and they are on. |
| **Overridden** | The prompt has an override, and it is on. |
| **Outdated** | The built-in prompt changed after you wrote the override. See [Outdated overrides](#outdated). |
| **Error** | A text of the prompt has a placeholder error. See [Errors](#errors). |
| **Global changes** | Only in **Repository prompts**. The System prompts change this prompt. |

## Edit a prompt [#edit-a-prompt]

<ProductDemo id="prompts" />

<Steps>
<Step>Open **System prompts** or **Repository prompts**. See [Find a prompt](#find-a-prompt).</Step>
<Step>Select the workflow, for example **Spec, Plan, Build**. For the instructions of a role, select the role in **Agent roles** instead.</Step>
<Step>Select the prompt, for example **QA Kickoff**. The prompt opens, with a back link to the screen that you left.</Step>
<Step>Type your text in **Append instructions**. The append turns on, and the **Appended** badge shows. **Final text** shows your text after the built-in text.</Step>
<Step>Select <Action>Save settings</Action>.</Step>
</Steps>

The line under the name of the prompt tells you what your change affects. For example: `Your changes apply to every task of Spec, Plan, Build, in every repository.` In Repository prompts, it ends with `in this repository only.`

### Replace the whole prompt [#replace]

<Steps>
<Step>Open the prompt, and select <Action>Replace</Action> in **Replace the whole prompt**.</Step>
<Step>Edit the text in **Replacement prompt**. It starts with the built-in text. In Repository prompts, it starts with the global override when that override is on.</Step>
<Step>Select <Action>Save settings</Action>.</Step>
</Steps>

To compare your text with the built-in prompt, select <Action>View built-in text</Action>.

### Turn off or remove a change [#restore]

- To stop a change but keep its text, turn off its switch, then select <Action>Save settings</Action>.
- To delete a change, select <Action>Remove append</Action> or <Action>Remove override</Action>, then <Action>Save settings</Action>.
- If you delete all of the text of an append, OpenDucktor removes the append.

## Placeholders [#placeholders]

A placeholder such as `{{task.title}}` becomes its value when OpenDucktor sends the prompt:

```md title="Append instructions of Builder Kickoff"
Work on {{task.title}} in small commits.
Run the tests before you send build-completed for task {{task.id}}.
```

To add a placeholder, put the cursor in the text, then select the placeholder in **Insert a placeholder**. The buttons show only the placeholders that the prompt can fill. **Final text** marks each placeholder. It crosses out a placeholder that the prompt cannot fill.

These placeholders work in all prompts:

| Placeholder | Becomes |
|---|---|
| `{{task.id}}`, `{{task.title}}`, `{{task.issueType}}`, `{{task.status}}`, `{{task.description}}` | The task fields. An empty field becomes `(none)`. |
| `{{role}}` | The role, for example `build`. |
| `{{role.allowedTools}}` | The OpenDucktor tools of the role. |

In **Read-Only Permission Rejection**, the task placeholders have no task data. `{{task.id}}` becomes `permission-policy`, and the other task fields become `(none)`.

These placeholders work only in some prompts:

| Placeholder | Becomes |
|---|---|
| `{{humanFeedback}}` | The changes that you asked for in **Request Changes**. Only in **Builder Kickoff After Human Changes**. |
| `{{git.targetBranch}}` | The target branch of the task. Only in **Pull Request Generation Kickoff** and **Builder Git Conflict Message**. |
| `{{git.operationLabel}}`, `{{git.currentBranch}}`, `{{git.conflictedFiles}}`, `{{git.conflictOutput}}` | The stopped Git operation, its branch, its conflicted files, and its output. Only in **Builder Git Conflict Message** and **Pull Request Generation Kickoff**. In **Pull Request Generation Kickoff**, they become `(none)`. |

### Required placeholders [#required-placeholders]

An override of **Builder Kickoff After Human Changes** must keep `{{humanFeedback}}`. An override of **Pull Request Generation Kickoff** must keep `{{git.targetBranch}}`. Without them, the Builder does not get your changes or the target branch. An append does not need them, because the built-in text or the override has them.

## Goal Writer [#goal-writer]

**Goal Writer** tells a model how to write the goal of a step in [Goal mode](/coding-sessions/#goal-mode). <Action>Generate goal</Action> in the start dialog sends it to the [Default model](/settings-reference/#repository-agents-default-model) of the repository, with the task material and the default goal.

Goal Writer can fill only the placeholders that work in all prompts. A change applies the next time that you select <Action>Generate goal</Action>.

## Keep the workflow working [#keep-it-working]

<Callout type="warn" title="Keep the tool instructions">
Agents save their work and move the task only with the OpenDucktor tools. In an override, keep `{{role.allowedTools}}` in **Tool Protocol**. Keep `{{task.id}}`, tool names such as `odt_apply_workflow_event`, and event names such as `build-completed`.
</Callout>

An append keeps these instructions, because the built-in text stays in the prompt.

## Outdated overrides [#outdated]

An OpenDucktor update can improve a built-in prompt. Your override keeps your text, and the prompt gets the **Outdated** badge. When you open the prompt, **The built-in prompt changed** shows:

- Select <Action>View built-in text</Action> to read the new version.
- Select <Action>Keep my override</Action> to keep your text. The badge goes away.
- Select <Action>Remove override</Action> to use the built-in prompt again.

Then select <Action>Save settings</Action>.

## Errors [#errors]

An error on a prompt blocks <Action>Save settings</Action>. The footer names the first prompt with an error, for example `Fix the placeholder error in QA Kickoff (Spec, Plan, Build, System prompts).` With more errors, it starts with `Fix 2 prompt placeholder errors. The first is in`. The prompt, its workflow, and its section in the sidebar show the error. To save your other changes first, turn off the change that has the error.

These errors show under the text in Settings:

| Error | Fix |
|---|---|
| `Unsupported placeholder: {{name}}.` | Fix the name, or remove the placeholder. See the [placeholder tables](#placeholders). With more than one, the message starts with `Unsupported placeholders:`. |
| `This prompt cannot fill {{humanFeedback}}.` | The placeholder exists, but not in this prompt. Remove it, or use one of the buttons in **Insert a placeholder**. |
| `Missing required placeholder: {{humanFeedback}}.` | Add the [required placeholder](#required-placeholders) to the override again. With more than one, the message starts with `Missing required placeholders:`. |

A change that you saved in an earlier version can stop a session start or a message with an error such as this one:

```txt
The global append of prompt "messages.qa_review" has a placeholder problem. This prompt cannot fill {{humanFeedback}}. This prompt can fill: {{role}}, {{role.allowedTools}}, {{task.id}}, {{task.title}}, {{task.issueType}}, {{task.status}}, {{task.description}}. Edit or turn off this append in Settings.
```

The message names the layer: `global` or `repository`, then `override` or `append`. The quoted value is the prompt ID, for example `messages.qa_review` for **QA Kickoff** or `build.instructions` for **Builder Instructions**. Open the prompt, then fix the text or turn off that layer.
